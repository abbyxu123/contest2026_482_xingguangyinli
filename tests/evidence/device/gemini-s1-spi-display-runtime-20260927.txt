Display-path finding and correction
-----------------------------------
The board configuration enabled both the R528 DISP2 framebuffer provider and
the NuttX LCD framebuffer while the Gemini-S1 panel is connected through the
ILI9341 hardware-SPI path. Link inspection showed that the DISP2 provider won
the framebuffer symbols, although the panel's parallel TCON data pins are not
used by this board configuration.

The verified integration candidate therefore:

1. excludes DISP2 dev_fb.c when CONFIG_LCD_ILI9341_HARDWARE_SPI is enabled;
2. lets the generic NuttX lcd_framebuffer provide /dev/fb0;
3. uses board_lcd_initialize/board_lcd_getdev from ili9341_lcd_spi.c;
4. adds the required board_lcd_uninitialize entry point and negative errno;
5. leaves the Living Canvas application, touch driver, resource partition and
   NAND layout unchanged.

Current product-calibration boundary
------------------------------------
This run verifies the hardware-SPI display path and the Living Canvas on-panel
runtime. The tested configuration is landscape (320 x 240). The final product
layout is portrait (240 x 320), so panel orientation and matching touch
coordinates remain a separate calibration gate.

The QR component rendered correctly, but the URL supplied for this engineering
run was not a public product handoff endpoint. It is not represented as a
completed mobile order flow. Final evidence must use a publicly reachable URL
whose on-screen description matches its actual destination.
